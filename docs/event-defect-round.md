# 이벤트 매매 시스템 — 적대적 검증과 결함 수정 기록 (2026-08-22)

유목민식 이벤트 단타 시스템을 만든 직후, 다섯 모듈(`material` / `event-engine` /
`event-plan` / `event-sources` / `telegram`)을 적대적으로 검증하고 나온 결함을
TDD로 수정한 기록이다. 수정자와 별개의 검증자가 **뮤테이션 172종 + 실제 픽스처
전 구간 + 퍼즈 3만여 건**으로 재확인했다.

이 문서를 남기는 이유는 결함 목록 자체가 아니라, **결함이 살아남는 방식**이
두 패턴으로 반복되기 때문이다. 다음 사람은 여기부터 의심하면 된다.

---

## 1. 가장 큰 발견 — 시황 층이 처음부터 조작된 값으로 돌아갔다

`src/bithumb.js`의 `parseTickerAll`이 종가와 거래대금만 읽고 **24시간 변동률
(`fluctate_rate_24H`)을 통째로 버렸다.** 시황 판정의 유일한 입력이다.

그런데도 아무 오류가 나지 않았다. 데몬이 없는 값을 이렇게 채우고 있었기 때문이다:

```js
btcChange24hBps: btc && typeof btc.changeRate === 'number' ? btc.changeRate * 10000 : 0,
breadthPct: t.length ? (ups / t.length) * 100 : 50,
```

`changeRate`가 전 종목에서 `undefined`였으므로 실제로 계산된 값은:

| 항목 | 실제 계산값 | 진짜 값 (같은 시각) |
|---|---|---|
| BTC 24h | **0bps** (위장) | +683bps |
| 시장폭 | 상승 0건 ÷ 476 = **0%** | 94.96% |
| 판정 | **risk_off** (문턱 40% 아래) | risk_on |
| 익절 배수 | **×0.7** | ×1.3 |

**켜져 있던 내내 익절폭이 1.86배, 그것도 반대 방향으로 어긋나 있었다.**
`assessMarketContext`는 입력이 없으면 `regime: null`을 돌려주도록 올바르게
설계돼 있었고, `planEventTrade`는 `regime`이 null이면 계획을 만들지 않는다.
잘 맞물린 사슬이었는데 **호출자가 빈 값을 채워 넣어 사슬 전체를 무력화했다.**

0과 50은 하필 완벽하게 중립적인 값이라 어떤 가드에도 걸리지 않는다. 그래서
이 실패는 로그 한 줄 남기지 않았다.

수정: 파서가 변동률을 읽고(없으면 `null`), `src/market-snapshot.js`가 위장 없이
입력을 만들고, 데몬이 시황을 못 읽으면 **진입하지 않는다.** 시황에 나이도 붙여
15분이 지나면 스스로 만료시킨다 — 한 시간 전 국면으로 지금 재료의 크기를 정하는
것은 모르는 것보다 나쁘다.

---

## 2. 반복되는 실패 방식 ① — 값 없음을 그럴듯한 기본값으로 위장

같은 날 네 건이 나왔다.

| 자리 | 위장 | 결과 |
|---|---|---|
| 데몬 시황 입력 | `0` / `50` | 영구 risk_off (위 1번) |
| 데몬 시황 초기값 | `neutral, ×1` | 켠 직후 재료가 "시황 중립"으로 계획됨 |
| `excessReturn` (기존) | `null` 유지 ✅ | 0으로 했으면 하락장 전체가 "고유하락" |
| `onPriceTick`의 모르는 가격 (기존) | `null` 유지 ✅ | 0이면 −100% 거짓 기록 |

앞의 둘이 결함이고 뒤의 둘은 이미 옳게 되어 있었다. **차이는 그 자리를 쓴
사람이 "0은 확정된 관측이고 null은 관측 없음"을 구분했는가뿐이다.**

**판별법:** "모르면 null을 돌려준다"고 잘 설계된 함수를 찾은 뒤, **그 호출자가
null을 만들어 넘길 수 있는지** 확인한다. 설계는 옳은데 호출자가 무력화하는 경우가
대부분이다.

---

## 3. 반복되는 실패 방식 ② — 모듈은 고쳤는데 호출처가 안 읽는다

수정 에이전트에게 파일 범위를 좁게 주면 반드시 이 모양이 남는다.

| 고친 것 | 남은 증상 |
|---|---|
| `classifyMaterial`이 `candidateTickers`를 내준다 | 읽는 쪽 3곳이 모름 → **S급 상장·상장폐지 공지가 종목명 없이 알림에 나감** |
| 엔진에 `onExitFailed` 추가 | 유일한 호출처가 여전히 `halt` → 청산 실패 시 포지션이 HALTED에 수량을 든 채 고아 |
| `low`/`high` 방어 추가 | 데몬이 안 넘김 → 도달 불가 코드 |

세 건 모두 **단위 테스트는 전부 초록이었다.** 이음매는 단위 테스트가 원리적으로
못 잡는다. 픽스처를 파서 → 분별기 → 계획 → 엔진 → 포매터까지 통째로 흘리는
재현 스크립트가 유일한 검출 수단이었다.

## 4. 수정이 새 결함을 만든 경우

D1(해제 공지가 악재로 분류됨)을 고치려고 해제 규칙을 중단 규칙 위로 올렸더니,
**순수 중단 공지가 재개로 넘어갔다.** 거래소가 중단 공지에 재개를 예고로 얹기
때문이다("재개 시 별도 공지", "중단 및 재개 일정 안내"). 고치려던 것과 정확히
같은 계열(방향 뒤집힘)의 결함이 반대편에 생겼다.

가름의 기준은 **해제가 중단에 직접 붙었는가**다. `중단 해제`만 재개로 본다.

같은 수정의 부작용이 하나 더 있었다. 유의해제가 bearish에서 bullish로 바로잡히면서
**A급이 매매 하한(`minGrade: "A"`)과 정확히 일치**해, 결함 수정의 부작용으로
자동 진입 경로가 열렸다. 안도 랠리의 폭은 이 저장소가 한 번도 재본 적이 없다.
B급으로 내렸다 — **방향만 아는 재료는 알림까지다.**

---

## 5. 배포 게이트 자신의 구멍

수정 작업 중 게이트를 돌렸더니 **통과했다.** 그 순간 다른 프로세스가 검증을
위해 소스에 결함을 심어 둔 상태였다. 게이트는 "테스트가 통과했는가"만 보고
**"그 테스트가 어느 코드에 대한 것인가"는 보지 않았다.**

커밋되지 않은 코드는 되돌릴 대상이 없다 — `version-log`가 배포 기록에 커밋
해시를 요구하는 것과 같은 이유다. `TREE_DIRTY` 차단을 추가했다.

---

## 6. 조언 문자열도 테스트 대상이다

`planEventTrade`가 최소 주문금액 미달일 때 내는 진단 문구가 **틀린 손잡이를
가리키고 있었다.** 자본 3,000원에 "위험 비중을 1.67%로 올리세요"라고 적는데,
레버리지가 없어 명목은 자본을 넘지 못하므로 어떤 비중으로도 5,000원에 닿지 않는다.
하필 기본 설정(비중 1%, B급 손절 100bps)이 정확히 그 경우였다.

이 문자열의 존재 이유가 08-17 사고(계좌가 쪼그라들어 모든 신호가 사이징에서
조용히 사라짐) 재발 방지다. **조언이 틀리면 존재 이유를 잃는다.**

격자 테스트(등급 3 × 자본 8 × 비중 7)로 **조언대로 다시 계산해 정말 최소
주문금액을 넘는지**까지 확인하도록 바꿨고, 그 테스트가 두 번째 결함도 찾아냈다 —
필요한 비중을 소수 둘째 자리에서 **내림**해 적어, 적어준 숫자를 그대로 넣으면
여전히 미달이었다(39,000원·0.05%에서 조언 0.19% → 명목 4,940원).

## 7. 시간대 약어 하나가 재료를 되살린다

`CST`는 미 중부(−0600)이자 중국 표준시(+0800)다. V8은 −0600으로 읽으므로
중화권 피드가 `CST`를 쓰면 시각이 **14시간 늦게** 찍힌다. 그 방향이 하필
"오래된 공지가 방금 뜬 것처럼 보이는" 쪽이라, 신선도 필터를 그대로 통과해
**이미 시장에 퍼진 재료로 진입하게 된다.**

이 모듈은 `KST`를 임의로 +09:00이라 단정하지 않기로 이미 정해 두었다. 뜻이 둘인
약어에도 같은 규칙이 적용돼야 한다. `E`/`M`/`P` 계열은 뜻이 하나뿐이라 남겼다 —
전부 빼면 그 피드가 통째로 사라지는 원래 문제로 돌아간다.

## 8. 남은 것

- **감시 모드의 표본이 0건이다.** 이 전략은 백테스트가 불가능하므로(공지 API가
  과거를 소급 제공하지 않는다) 감시 모드의 가상 포지션 추적이 유일한 근거다.
  복기·보정·롤백 모두 30건 문턱을 두고 있어, 그때까지는 어떤 파라미터도 바꾸지 않는다.
- **`candidateTickers`는 검증되지 않은 값이다.** 괄호 안 대문자 토큰이면 통과하므로
  진짜 심볼이 아닌 약어가 섞일 수 있다. 기록·표시용이고 주문 심볼로 쓰면 안 된다.
- **`MARKET_NAMES`는 고정 목록**이다. 거래소가 새 마켓을 열면 그 이름이 티커
  후보로 새어 나온다.
